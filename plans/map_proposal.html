VN Address Widget App

Nhận vào lat/lng, trả về địa chỉ phân cấp hành chính Việt Nam — hiển thị trực tiếp trên màn hình home.

01 — Bài toán

Map trả về địa chỉ không đủ cấp

Vấn đề thực tế

Khi chấm một điểm trên map, API thường trả về một chuỗi địa chỉ không nhất quán — đôi thiếu cấp huyện, đôi thiếu cấp xã, không theo chuẩn phân cấp hành chính 3–4 cấp của Việt Nam. Muốn lấy địa chỉ đầy đủ từ tọa độ phải mở app, chờ load, rồi tự đọc.

App này giải quyết bằng cách: offline geocoding với boundary data tự quản lý + widget luôn sẵn ngoài màn hình home.

Những gì app làm

05 — Design Rules

Nguyên tắc thiết kế

Áp dụng Hallmark modern-minimal — genre dành cho utility tool, dev-adjacent. Mọi quyết định màu, chữ, spacing đều có rule cụ thể, không phải cảm tính.

Color System

OKLCH — không dùng hex hay HSL

Typography

2 + 1 font — không hơn

Display + Body dùng cùng family (Geist). Mono (JetBrains) là outlier cho coordinates, labels, timestamps — xuất hiện tối đa 2 role, không phải font thứ ba tràn lan.

Geist 700 · display / heading
Geist Regular 400 · body / UI
JetBrains Mono 400 · coords, labels
Tracking: -0.03em trên display, +0.08em trên mono labels.
Spacing

4pt base — mọi value là bội số

Padding, gap, margin đều là bội của 4px. Không có giá trị lẻ như 7px hay 11px — đảm bảo alignment nhất quán khi code thật.

06 — Kiến trúc

Luồng xử lý

GPS / Input lat,lng │ ▼ ┌─────────────────────────────────────────┐ │ R-tree Spatial Index │ ← boundary polygons │ Lọc nhanh bằng bounding box │ loaded vào RAM │ → ~5 polygon candidates │ lúc app khởi động └─────────────────┬───────────────────────┘ │ ▼ ┌─────────────────────────────────────────┐ │ Point-in-Polygon │ │ Test thật sự trên candidates │ │ → match Tỉnh / Huyện / Xã │ └─────────────────┬───────────────────────┘ │ ▼ ┌─────────────────────────────────────────┐ │ Cache Layer │ │ Lưu kết quả theo bbox cell │ │ → tọa độ gần nhau không query lại │ └─────────────────┬───────────────────────┘ │ ┌───────┴────────┐ ▼ ▼ App Screen Home Widget (3 cấp đầy đủ) (compact display)

Boundary data (~30MB) được bundle sẵn trong app — hoạt động hoàn toàn offline. Không gọi API ngoài cho 3 cấp hành chính. Tên đường/số nhà (nếu cần) mới fallback sang Nominatim.

07 — Data Layer

Boundary data & cập nhật

CấpNguồn gốcCập nhật khi nàoKích thước
Tỉnh / TP GADM + tự merge sáp nhập 2025 Rất hiếm (vài năm/lần) ~2 MB
Quận / Huyện GADM + tự merge 1–2 năm/lần ~8 MB
Phường / Xã OSM Geofabrik Theo đợt sáp nhập lớn ~20 MB

Khi sáp nhập xảy ra: ST_Union(polygon_A, polygon_B) → cập nhật tên/mã → ship data update qua OTA hoặc app update nhỏ.

09 — Lộ trình

Các giai đoạn phát triển

M1

MVP — Geocoder lõi

1–2 tuần
  • Load GADM data, build R-tree index
  • Point-in-Polygon trả về 3 cấp
  • Screen tra cứu: nhập lat/lng + hiển thị kết quả
  • Copy address 1 chạm
M2

Widget

1–2 tuần
  • Widget nhỏ: vị trí hiện tại (GPS auto-update)
  • Widget lớn: 3 cấp + tọa độ
  • Background location permission handling
  • Cache tránh query lại khi ít di chuyển
M3

Map picker + Lịch sử

1 tuần
  • Tap on map → lấy địa chỉ điểm đó
  • Lịch sử 20 điểm gần nhất
  • Export danh sách
M4

Data maintenance tooling

1 tuần
  • Script merge polygon khi sáp nhập
  • Validate data sau mỗi lần update
  • OTA data update (không cần release app)
