# iOS scaffolding — manual Xcode setup required

Per [ADR 0002](../../docs/decisions/0002-architecture-system-design.md), this session ran on Windows with no Xcode/macOS available, so **these are source files only — the Xcode project itself (`Runner.xcodeproj`) does not exist yet and was not hand-authored**, since `.pbxproj` is a generated format that's unreliable to write by hand. This must be done once on a Mac, by someone who can verify it builds.

## Steps (on a Mac, after Flutter + Xcode are installed)

1. From `app/`, run `flutter create --platforms=ios .` to generate a real `ios/Runner.xcodeproj` — this repo already has `app/lib/`, `app/pubspec.yaml`, etc., so `flutter create` will only fill in the platform folder.
2. Replace the generated `ios/Runner/AppDelegate.swift` and `ios/Runner/Info.plist` with the ones in this directory (`app/ios/Runner/`).
3. In Xcode: **File → New → Target → Widget Extension**, named `Widget`, "Include Configuration Intent" unchecked. This creates the extension target and embeds it in `Runner.app` automatically.
4. Replace the generated widget target's Swift files with `app/ios/Widget/VnaddrWidget.swift` and `VnaddrWidgetBundle.swift`; replace its `Info.plist` with `app/ios/Widget/Info.plist`.
5. Add `core/include/vnaddr.h` to the `Widget` target and set its **Objective-C Bridging Header** build setting to `app/ios/Widget/Widget-Bridging-Header.h` (per ADR 0002 §9 — the extension calls the core directly from Swift at link time, no Dart FFI involved).
6. **Signing & Capabilities** on both `Runner` and `Widget` targets: add the **App Groups** capability, group `group.com.vnaddress.widget` (matching `Runner.entitlements` / `Widget.entitlements` in this directory) — replace with your real Team ID's group identifier.
7. Build `core/` for iOS (`cargo build --target aarch64-apple-ios` and the simulator target, then `xcodebuild -create-xcframework` per ADR 0002 §9) and add the resulting `VnAddr.xcframework` to both targets, **Embed & Sign** on `Runner`, **Do Not Embed** on `Widget` (statically linked, per §9).
8. Set **Strip Style: Non-Global Symbols** on both targets' build settings, and confirm the linker keeps `vnaddr_*` symbols (`-force_load` or an exported-symbols list) — see ADR 0002 §9 for why both are needed.
9. Set **iOS Deployment Target** to 16.0 on both targets (ADR 0002 §6).

## What's provided here vs. generated by Xcode

| Provided in this repo | Generated by `flutter create` / Xcode wizard |
|---|---|
| `Runner/AppDelegate.swift`, `Runner/Info.plist`, `Runner.entitlements` | `Runner.xcodeproj`, `Runner/Main.storyboard`, `Runner/LaunchScreen.storyboard`, `Runner/Assets.xcassets` |
| `Widget/VnaddrWidget.swift`, `VnaddrWidgetBundle.swift`, `Info.plist`, `Widget.entitlements`, `Widget-Bridging-Header.h` | the `Widget` extension target itself, its build settings, its embed-in-Runner build phase |

Once step 1–9 are done and committed, this README should be deleted and the real project treated as source of truth.
